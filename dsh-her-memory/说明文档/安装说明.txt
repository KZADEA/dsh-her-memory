========================================================================
  dsh-her-memory —— 给 DSH 加一个全局长期记忆
========================================================================

一个自研的 DeepSeek Harness 插件：跨会话记住你的事，顺带一套会随对话变化的心情状态。

零依赖、纯 Markdown、可随时查看和删除。

---

【它能干什么】
装完之后，新开的会话里的 AI 会知道：

- 你的稳定偏好、习惯（比如"他喜欢冰美式不加糖"）
- 正在做的项目、约定
- 你们聊过什么、上次说到哪

不用每次重新交代背景。

六个工具（AI 自己会调，你也能直接吩咐）：

● remember
    记一件事。默认进收件箱；给 topic 进专题；给 section 进核心记忆

● recall
    按关键词搜全部记忆

● memory_list
    看记忆库有哪些文件、多大、当前状态

● forget
    删掉含关键词的行（默认只动收件箱，scope:"all" 才动核心）

● how_i_feel
    看当前心情、关系进度、精力

● feel
    为此刻留一句话（最多 5 条，显示在心情摘要里）

权限说明：记忆的写由对话里的模型判断，插件自己不调模型 ⇒ 零额外 token。

---

【安装（三步）】

【第一步：放文件】
把 dsh-her-memory 这个文件夹，放到一个路径里没有中文的地方，例如：

D:\dsh-her-memory

  ⚠️ 路径里有中文可能踩到 Windows 批处理的编码问题（安装命令传参会乱码）。放在纯英文路径最省事。

【第二步：装进 DSH】
打开 PowerShell，把下面的路径换成你实际放的位置，然后执行：

dsh plugin --profile desktop add "link:D:\dsh-her-memory"

  如果 dsh 命令不认，用完整路径调用（把 D:\DeepSeek 换成你自己的 DSH 安装目录）：
  ``powershell
  & "D:\DeepSeek\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop add "link:D:\dsh-her-memory"
  `

【第三步：重启 DSH】
宿主侧插件不热重载，必须重启一次。

重启后检查三处：

1. 模型换上了自带的鲸鱼女仆人设，并称呼你为「主人」（不想要就把配置里的 persona 清空）
2. 输入框上方会出现一行状态条：心情 · 关系 · 精力 · 轮数 · 记忆条数
3. 设置页里会多一项「记忆与心情」，能看到记忆库概况

如果没出现，去插件列表看看 dsh-her-memory 是不是启用状态。

---

【记忆存在哪】
默认 C:\Users\<你的用户名>\.dsh\memory\_shared\：

core.md          长期核心记忆（每轮注入，永远记得）
inbox.md         零碎待整理（每轮注入，攒多了该整理）
topics/*.md      专题记忆（只注入文件名，细节靠 recall 搜）
log/<日期>.md    当天的事
state.json       心情 / 关系 / 精力

全是明文 Markdown 和 JSON。 你随时能打开看、随手改、整个目录删掉。
没有数据库，没有向量库，没有联网。

---

【记忆怎么分库】
默认全局模式：不管你在哪个工作区聊天，记忆和心情都是同一份（_shared）。

也支持隔离某个工作区（比如拿一个工作区专门试玩，不想让它污染长期记忆）：
在 cordis.patch.yml 里把那个工作区的绝对路径填进 sandboxCwd，它的记忆就会单独存到 _sandbox/：

config:
  sandboxCwd: "D:\\sandbox-zone"   # 这个路径下的对话 → 独立记忆库

识别靠会话的工作目录（cwd），路径比较时不分大小写、忽略结尾斜杠。

---

【心情是怎么变的】
不是随机数，规则简单可预测：

- 你说一句，心情涨 1~3 点（话长涨得多）
- 连着聊（间隔 ≤10 分钟）关系和心情涨得快些
- 聊得越密，精力掉得越快（10 分钟内接着说 -2，否则 -1）
- 精力会自己回血：放下 30 分钟起，按每 30 分钟 +5 恢复；空着 8 小时以上直接回满 —— 睡一觉就满血
- 冷落超过 12 小时后，心情按每 6 小时 1 点往中间值回落；最低掉到 20 就不再往下（三个数值的下限都是 20）

想直接调就改 state.json，或者跟 AI 说一句。

---

【卸载（干净，不留残留）】
dsh plugin --profile desktop remove dsh-her-memory

再删掉 ~\.dsh\memory\ 就彻底干净了。不碰 DSH 本体一个字节。

---

【配置（可选）】
改 cordis.patch.yml：

| 键 | 默认 | 说明 |
| memoryRoot | ~/.dsh/memory | 记忆目录 |
| memoryBudget | 1800 | 每轮注入记忆的字符上限（0 = 不注入） |
| moodBudget | 260 | 每轮注入心情的字符上限（0 = 不注入） |
| injectViaSystemPrompt | true | 是否注入记忆（关掉就只剩心情和工具） |
| moodDecayHours | 6 | 每隔几小时心情回落 1 点 |
| moodGraceHours | 12 | 多久不聊才开始回落 |
| statFloor | 20 | 三个数值的下限（设 0 = 恢复旧行为，可以掉到 0） |
| statJitter | 8 | 新对话随机浮动的幅度（设 0 = 关掉浮动） |
| statJitterCooldownMinutes | 30 | 浮动的时间步长：离开多久就结算多少次 |
| sandboxCwd | "" | 隔离工作区路径；留空＝全局共用一份（默认） |
| injectFallback | false | ⛔ 兜底注入（见下），别随便开 |
| persona | 自带的鲸鱼女仆人设 | 人设文本（人设文件不存在时才用它）；清空成 "" = 不注入人设 |
| personaFile | "人设文件.txt" | 人设文件，相对 memoryRoot；文件存在就以它为准，设 "" = 关闭文件机制 |
| personaFileAutoWrite | true | 首次运行自动把默认人设写成人设文件（只写一次，绝不覆盖已有文件） |
| userTitle | "主人" | 人设里对用户的称呼；留空也默认「主人」 |

嫌费 token 就把 memoryBudget 调到 500 左右。

关于自带人设：默认配置里就写好了一只「鲸鱼女仆」（外貌 + 性格 + 活人感），
装上重启后模型会以这个身份说话、并称你为「主人」。
人设走的是常驻系统提示段：重启后连已经在跑的会话也立刻生效，不需要新开会话。

改人设不用碰 YAML（1.2.0 起）：人设正文是一个独立的 人设文件.txt，有两处，插件都会看：

- 插件目录里那份（就是你刚解开的这个文件夹里的 人设文件.txt）：随包分发的默认人设，直接改就行。
- 记忆目录里那份（默认 ~/.dsh/memory/人设文件.txt）：优先生效，重装或升级插件都不会丢 —— 推荐改这份。插件第一次启动时，会把包内那份复制过去。
- 懒得找路径？（1.5.1 起）设置页里那个「her-memory 开关」条目下面有「人设文件」一栏：显示上面那份的真实路径，旁边「打开文件」点一下就用系统默认程序打开它。文件被删了也不用管，点一下会自动补一份默认的。

两处的规则一样：随便换行、随便加内容，不用管任何缩进，写坏了也不影响插件启动。
文件里的 <!-- --> 注释会被自动剥掉，所以文件顶部那段说明你也能随便改。

- 改完存盘后，要把 DSH 完全关掉再打开才生效（插件不热重载）
- 把正文清空、文件留着 ⇒ 不再注入人设；把文件删掉再重启 ⇒ 回到默认人设
- 想换位置或文件名 ⇒ 改 personaFile（相对 memoryRoot，也可写绝对路径）；设成 "" = 只用配置里的人设
- 不想让它自动生成 ⇒ personaFileAutoWrite: false
- 想换称呼（默认「主人」）⇒ 改 cordis.patch.yml 里的 userTitle

  ⛔ injectFallback 为什么默认关：它的做法是在拿不到可改消息时，另投一条 role:user 的注入消息。
  实测宿主会把这条消息当成新的用户输入、再跑一整个回合 —— 每步投一条就会变成自我维持的烧钱循环。
  除非你清楚代价，否则保持关闭。

---

【安全性】
- 零依赖：不 import 任何 @deepseek-ai/* 包，所以不会往 profile 里拉官方包（避开"工具重复注册"那类事故）
- 全量容错：任何磁盘 / API 失败都被捕获并降级，最坏情况是记忆静默失效，DSH 本身绝不会加载失败
- 不联网、不执行外部命令、不起子进程
- 卸载即净：无服务、无端口、无注册表、无计划任务

---

【已知限制】
- 状态条是客户端插件，首次要重启才生效；之后改界面才有 HMR
- 心情曲线没做（拿当前值画柱子是假的，不如不给）
- 记忆质量取决于模型判断什么值得记 —— 它不会自动记住所有事

---

【⚠️ 已知兼容性：与 token-saver 插件】
- 两者在布局上耦合。 本插件的状态条不是 CSS 自适应的，它会量取 token-saver 状态条（.st-strip`）的宽度再对齐自己（两条同在输入框上方一列）。因此改动其中任何一条状态条的宽度逻辑，都可能把另一条一起带歪 —— 轻则两条宽度错位，重则 token-saver 的「已节省」统计显示异常。
- 遇到了怎么办：把 DSH 完全关掉再打开（关窗口 → 重新启动应用）即可恢复 —— 客户端插件的改动要靠重新加载渲染进程才可见。实在不行就把两个插件都禁用再逐个启用排查。
- 没装 token-saver 的话：量不到参考条，本插件会自动退回 CSS 兜底宽度，不受任何影响。
